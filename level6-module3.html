Level 6: SystemVerilog, Module 3

Arrays and Data Structures

Testbenches juggle collections of data: expected results, pending transactions, memory contents. SystemVerilog gives you four kinds of array, each suited to a different job. Here you'll operate on each one and watch it change.

Learning objectives

By the end of this module you will be able to:

  1. Index multidimensional packed and unpacked arrays correctly.
  2. Create, resize and delete dynamic arrays with new[].
  3. Use a queue with push_back, push_front, pop_back, pop_front, insert and delete.
  4. Apply array methods such as find, sort, reverse, sum and size.
  5. Model a sparse memory with an associative array.
  6. Pick the right array type for a given verification task.

Module 1: packed vs unpacked dimensions.

Fixed-size and multidimensional arrays

Fixed arrays have a size set at compile time. When you index, unpacked dimensions come first (left to right), then packed ones.

logic [7:0]  mem   [256];        // 256 bytes: one packed, one unpacked dimension
int          grid  [4][8];       // 4 x 8 ints, both unpacked
logic [3:0]  m     [2][3];       // 2 x 3 elements, each a 4-bit vector

m[1][2]      // element at row 1, column 2  -> a 4-bit value
m[1][2][3]   // bit 3 of that element
int total = $size(grid, 1);  // 4  (size of the first dimension)

Dynamic arrays

A dynamic array is declared with empty brackets [] and gets its size at run time with new[n]. It holds nothing until you allocate it.

Dynamic array playground Activity

int d[];   // declared, but size 0

Queues

A queue [$] grows and shrinks at both ends, like a line of people. It is the most-used container in testbenches: scoreboards keep expected transactions in a queue and pop them as the DUT produces results.

Queue simulator Activity

int q[$] = '{3, 5};

q[0] is the front and q[$] is the back. Popping an empty queue returns the default value (0 for int) and gives a warning, so check q.size() first.

Array methods

Arrays and queues share built-in methods for searching, ordering and reducing. Methods that search return a queue of results, because there may be zero, one or many matches.

Associative arrays

An associative array stores only the entries you write, indexed by any key type. It is ideal for a large, sparse space such as a 4 GB memory where the test touches only a few hundred addresses.

Sparse memory model Activity

bit [31:0] mem [bit [31:0]];   // key: 32-bit address, value: 32-bit data

Practice questions

Work these on paper first, then open the model answer.

1. Declare a queue of bytes, add 8'hAA to the back and 8'h55 to the front. What is q[0]?
byte q[$];
q.push_back(8'hAA);
q.push_front(8'h55);   // q = '{8'h55, 8'hAA}

q[0] is 8'h55, the front.

2. Resize a dynamic array d of 4 elements to 10 without losing its contents.
d = new[10](d);   // copies the old 4 elements, the rest are 0
3. Why is an associative array better than bit [31:0] mem [2**32] for a memory model?

The fixed array would try to allocate 232 × 4 bytes = 16 GB. The associative array stores only addresses that were written, so a test touching 500 addresses uses a few kilobytes.

4. Write code that returns all elements greater than 10 from int arr[].
int big[$];
big = arr.find(x) with (x > 10);
5. How do you safely read an associative array entry that might not exist?
if (mem.exists(addr)) data = mem[addr];
else                   data = '0;   // or report "read of unwritten address"
