Functions and Tasks

Functions and tasks package reusable code. The one rule to remember: a function finishes in zero simulation time, while a task may wait for clocks and delays. Everything else follows from that.

Learning objectives

By the end of this module you will be able to:

  1. Write functions that return a value and void functions.
  2. Write tasks that consume simulation time with delays and clock events.
  3. Decide whether a job needs a function or a task.
  4. Predict how input, output, inout and ref arguments move data.
  5. Explain why recursion and ref arguments need automatic.

Functions

A function computes a result from its arguments and returns immediately. It can be used inside an expression, and it cannot contain # delays, @ events or wait.

function automatic logic parity(input logic [7:0] d);
  return ^d;                 // XOR of all bits
endfunction

function automatic int max3(int a, int b, int c = 0);   // c has a default value
  int m = (a > b) ? a : b;
  return (m > c) ? m : c;
endfunction

function void print_pkt(int id, byte data);   // void: returns nothing
  $display("pkt %0d: data = %h", id, data);
endfunction

// Usage
logic p = parity(8'hA5);          // inside an expression
int   m = max3(.a(4), .b(9));     // named arguments, c uses its default
print_pkt(1, 8'h3C);              // a void function is called like a statement

Tasks and simulation time

A task is called as a statement and may take time: it can wait for clock edges, use delays and call other tasks. Testbenches use tasks for every protocol action: reset, write, read, send a packet.

task automatic send_byte(input byte data);
  for (int i = 0; i < 8; i++) begin
    @(posedge clk);
    tx <= data[i];           // LSB first, one bit per clock
  end
endtask

function automatic bit parity(input byte data);
  return ^data;
endfunction

Argument directions: input, output, inout, ref

input, output and inout copy values: in at the call, out when the task returns. ref passes a reference: the task works on the caller's own variable, so every change is visible immediately.

Watch the data move Activity

task automatic bump(<dir> int x);
  x = x + 10;      // at time 0
  #5;
  x = x * 2;       // at time 5
endtask

initial begin v = 1; bump(v); end           // process A
initial begin #2 $display("v = %0d", v); end // process B peeks at time 2

Use const ref to pass a large array without copying it while promising not to change it: function automatic int sum(const ref int a[]);

automatic vs static

A static subroutine has one copy of its arguments and local variables, shared by every call. An automatic one creates a fresh copy on each call, like functions in C. Subroutines in modules are static by default; in classes they are automatic.

Recursion on the call stack Activity

function <lifetime> int fact(int n);
  if (n <= 1) return 1;
  return n * fact(n - 1);
endfunction

initial $display("fact(4) = %0d", fact(4));

Always write function automatic and task automatic in testbenches unless you have a reason not to. Static tasks called from two processes at once share their variables and corrupt each other.

Practice questions

Work these on paper first, then open the model answer.

1. Write a function that returns the number of 1s in a 16-bit value.
function automatic int count_ones(input logic [15:0] v);
  int n = 0;
  foreach (v[i]) n += v[i];
  return n;
endfunction

The built-in $countones(v) does the same.

2. Write a task that drives rst_n low for 3 clock cycles, then high.
task automatic apply_reset();
  rst_n <= 0;
  repeat (3) @(posedge clk);
  rst_n <= 1;
endtask
3. Why can't a function call a task?

A function must complete in zero time. A task may wait, so calling it could make the function take time. The compiler forbids it. (A function can start a task inside a fork ... join_none, but that is an advanced pattern.)

4. With task t(output int x); x = 5; #10; x = 7; endtask and t(v);, when does v change and to what?

v changes once, when the task returns at time 10, to 7. Output arguments are copied back only at the end.

5. When would you pass an array by ref?

When the array is large (copying costs time), or when the task must modify the caller's array directly, for example pushing results into a queue owned by the caller.
