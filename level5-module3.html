Fault Simulation and Fault Coverage

How good is a test set? Fault simulation answers that by counting which faults each pattern catches.

1

  • Identify equivalent faults and dominant faults
  • Collapse a fault list and compute the collapse ratio
  • Describe serial fault simulation with fault dropping
  • Explain how parallel fault simulation uses bit-level parallelism
  • Calculate fault coverage for a test set
  • Relate fault coverage, yield and defect level
2

What is fault simulation?

In Module 1 you checked, by hand, whether one pattern detects one fault. A real chip has millions of faults and thousands of patterns. Fault simulation automates this: for a given test set, it finds which faults are detected and which are not.

The result is summarised as fault coverage:

Fault coverage = detected faults ÷ total faults × 100%

Fault simulation is used to grade test sets, to decide whether more patterns are needed, and to build fault dictionaries for diagnosing failing chips.

3

Fault equivalence and dominance

Every fault has a test set: the input patterns that detect it.

  • Two faults are equivalent if they have exactly the same test set. We only need to keep one of them.
  • Fault f1 dominates fault f2 if every test for f2 also detects f1. If we detect f2 we get f1 for free, so f1 can be dropped.

Pick a gate type, then select any two faults to compare their test sets.

For an n-input AND gate: all input s-a-0 faults are equivalent to output s-a-0, and output s-a-1 dominates each input s-a-1. That leaves only n + 1 faults to target instead of 2(n + 1).
4

Fault collapsing

Fault collapsing uses equivalence and dominance to shrink the fault list before simulation or test generation. The collapse ratio is the collapsed list size divided by the original size.

Collapse the fault list of Y = A·B + C in two steps and watch the list shrink.

5

Serial fault simulation

The simplest method: simulate the good circuit once, then simulate the circuit again for each fault, one at a time, and compare outputs.

A big saving comes from fault dropping: as soon as a fault is detected by one pattern, it is removed and never simulated again. Step through the simulation and compare the work with and without dropping.

6

Parallel fault simulation

A computer processes a 32-bit or 64-bit word in one instruction. Parallel fault simulation packs one circuit copy into each bit: bit 0 holds the good circuit and the other bits hold faulty circuits. One bitwise AND of two words simulates the same gate in every copy at once.

Here we use a 4-bit word: the good circuit plus three faulty copies. Change the inputs and compare each bit at the output with bit 0.

Other methods exist too. Deductive fault simulation propagates lists of faults through the gates, and concurrent fault simulation only re-simulates the gates where a faulty circuit differs from the good one. Commercial tools use concurrent-style methods.

8

Yield, coverage and defect level

Yield (Y) is the fraction of manufactured chips that are truly good. Defect level (DL) is the fraction of chips that passed the test but are actually bad. Customers see the defect level, measured in parts per million (ppm).

The Williams–Brown model links them with the fault coverage T:

DL = 1 − Y(1 − T)

11

What you learned

  • Fault simulation finds which faults a test set detects; fault coverage summarises the result.
  • Equivalent faults have identical test sets, so only one per class is kept.
  • A dominating fault is detected by every test of the fault it dominates, so it can be dropped.
  • For an n-input AND gate, collapsing reduces 2(n + 1) faults to n + 1.
  • Serial fault simulation handles one fault at a time; fault dropping removes detected faults early.
  • Parallel fault simulation packs good and faulty circuits into the bits of one machine word.
  • Defect level falls quickly as fault coverage approaches 100%, which is why industry aims for very high coverage.
