Level 6: SystemVerilog, Module 5

Object-Oriented SystemVerilog

Modern testbenches are built from classes. If you have never written object-oriented code, this module builds the picture step by step: a class is a blueprint, an object is a thing built from it, and a handle is how you point at that thing.

Learning objectives

By the end of this module you will be able to:

  1. Explain the difference between a class, an object and a handle.
  2. Write a class with properties, methods, a constructor new() and this.
  3. Predict what happens when handles are assigned and when objects are copied (shallow vs deep).
  4. Use static members shared by all objects.
  5. Extend a class with extends and call the parent with super.
  6. Explain how virtual methods give polymorphism, and why abstract classes cannot be constructed.

Classes, objects and handles

A class is a blueprint describing data (properties) and behaviour (methods). An object is one instance built from it with new(). A handle is a variable that points to an object; it starts as null.

class Packet;
  bit [7:0] addr;          // properties
  bit [7:0] data;

  function new(bit [7:0] a = 0);   // constructor
    addr = a;
  endfunction

  function void display();         // method
    $display("addr=%h data=%h", addr, data);
  endfunction
endclass

this and static members

this means "the object whose method is running". Use it when an argument has the same name as a property. A static property belongs to the class, not to any single object: all objects share one copy.

class Packet;
  static int count = 0;   // one copy, shared by every Packet
  int id;                 // one copy per object
  bit [7:0] addr;

  function new(bit [7:0] addr);
    this.addr = addr;     // this.addr = the property, addr = the argument
    count++;
    id = count;
  endfunction
endclass

Shallow vs deep copy

p2 = new p1; makes a shallow copy: a new object whose properties are copied from p1. But if a property is itself a handle, only the handle is copied, so both objects share the inner object. A deep copy also copies every inner object, and you write it yourself.

class Header;  int len;  endclass

class Packet;
  int     id;
  Header  hdr = new();          // a handle to another object

  function Packet copy();       // deep copy, written by hand
    copy = new();
    copy.id      = id;
    copy.hdr.len = hdr.len;     // copy the inner object's contents too
  endfunction
endclass

Inheritance: extends and super

A derived class extends a base class: it inherits every property and method and can add new ones or override existing ones. super calls the parent's version.

class EthPacket extends Packet;
  bit [47:0] mac;                        // new property

  function new(bit [7:0] addr);
    super.new(addr);                     // build the Packet part first
    mac = 48'h00_11_22_33_44_55;
  endfunction

  virtual function void display();       // override
    super.display();                     // reuse the parent's printing
    $display("  mac=%h", mac);
  endfunction
endclass

Polymorphism and virtual methods

A base-class handle can point to an object of any derived class. When you call a method through that handle, virtual decides which version runs: without it, the handle's type decides; with it, the object's actual type decides.

Which display() runs? Activity

Choose the object, whether display() is virtual, and call it through a Packet handle.

Packet h;          // base-class handle
h = <object>;
h.display();

Going the other way needs a check. A derived handle cannot simply take a base handle: use if ($cast(eth_h, h)), which succeeds only if h really points to an EthPacket.

Abstract (virtual) classes

A virtual class is abstract: a template that you can only extend, never construct. A pure virtual method has no body; every non-abstract child must implement it. Verification libraries such as UVM are built this way.

virtual class BaseTxn;
  pure virtual function string convert2string();   // no body
endclass

class WriteTxn extends BaseTxn;
  bit [7:0] addr, data;
  virtual function string convert2string();
    return $sformatf("WRITE %h <= %h", addr, data);
  endfunction
endclass

Practice questions

Work these on paper first, then open the model answer.

1. What is printed? Packet a = new(); Packet b = a; b.addr = 7; $display(a.addr);

7. b = a copies the handle, not the object, so a and b point to the same object.

2. Why must a derived constructor call super.new() first?

The base part of the object must be built before the derived part uses it. If the base constructor has arguments without defaults, the compiler cannot call it automatically, so you must call super.new(args) as the first statement.

3. Write a class Counter with a static property total that counts how many Counter objects exist.
class Counter;
  static int total = 0;
  function new();
    total++;
  endfunction
endclass
4. When is a shallow copy enough?

When the class contains only plain values (ints, bit vectors, enums), with no handles to other objects. Then the shallow copy already duplicates everything.

5. Why do verification libraries use virtual methods everywhere?

So that generic code (a driver, a scoreboard) can work with base-class handles, while each test supplies derived classes with specialised behaviour. The generic code never needs to change.
