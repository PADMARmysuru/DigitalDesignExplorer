Why do we test an IC?

A chip is built layer by layer on a silicon wafer, with wires thousands of times thinner than a human hair. Even in a clean room, a speck of dust, a slightly thin metal line or a missing contact hole can damage one chip while its neighbour on the same wafer is perfect.

So the design can be 100% correct and the manufactured chip can still be wrong. Testing is how we separate the good chips from the bad ones before they reach a customer.

Defect → fault → error → failure

These four words describe the same problem at four different levels. A defect is physical, a fault is its logical model, an error is a wrong signal value, and a failure is what the user notices.

Click each stage, or press play to follow one defect all the way to a system failure.

Not every defect causes a failure. If a faulty node is never used with the input that exposes it, the system may keep working, which is exactly why hidden faults are dangerous and tests must be chosen carefully.

Good circuit vs faulty circuit

The most common fault model is the stuck-at fault: a wire behaves as if it is permanently tied to 0 (stuck-at-0, s-a-0) or to 1 (stuck-at-1, s-a-1), whatever the inputs say.

Test stimulus and test response

A tester (automatic test equipment, ATE) applies a test pattern, also called the test stimulus, to the chip's inputs. The chip, now called the circuit under test (CUT), produces an output response. The tester compares it with the expected response that was calculated by simulating the correct design.

Below, the CUT is Y = A·B + C. Test a good chip first, then put a defective chip on the tester and find a pattern that catches it.

7

Controllability and observability

To test a node inside a chip we must do two things through the pins only:

  • Control it: drive the node to 0 or 1 using the primary inputs.
  • Observe it: make a change at that node show up at a primary output.

Think of a room deep inside a building. It is hard to reach (control) and hard to see into from the street (observe). Nodes deep inside a circuit are the same.

8

IC testing flow

Testing is not one step at the end. It appears at several points between the idea and the shipped chip. Faults found early are much cheaper to handle: a common industry rule of thumb says the cost of catching a bad part grows roughly ten times at each level, from wafer to package to board to system.

What you learned

  • A correct design can still produce faulty chips, because fabrication introduces random physical defects.
  • Verification checks the design before fabrication; testing checks every manufactured chip after fabrication.
  • A physical defect is modelled as a logical fault; an activated fault causes an error; an error that reaches the user is a failure.
  • A stuck-at fault makes a line behave as permanently 0 or 1.
  • An input pattern detects a fault only when the good and faulty circuits give different outputs.
  • Testing means applying a stimulus, capturing the response and comparing it with the expected response: PASS or FAIL.
  • Controllability and observability describe how easily an internal node can be set and seen from the pins.
  • Chips are tested at wafer level and again after packaging, because catching faults early saves cost.
