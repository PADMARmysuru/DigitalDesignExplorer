Interfaces and Advanced SystemVerilog

Real designs connect blocks with buses of many signals. Interfaces bundle those signals into one named object; modports give each side its directions; clocking blocks remove testbench races; packages share definitions everywhere.

Learning objectives

By the end of this module you will be able to:

  1. Replace long port lists with an interface.
  2. Use modport to give each block the right signal directions.
  3. Explain how a clocking block avoids sampling races in testbenches.
  4. Connect a class-based testbench to the DUT with a virtual interface.
  5. Share types and constants with package and import, and know when `include is appropriate.
  6. Write modules with value parameters and type parameters.

Interfaces: one bundle instead of many wires

Without an interface, every signal of a bus appears in the port list of every module and at every instantiation. Add one signal and you edit every file. An interface declares the bundle once.

interface bus_if (input logic clk);
  logic        valid, ready;
  logic [7:0]  addr;
  logic [31:0] data;
endinterface

module master (bus_if bus);          // one port instead of five
  always_ff @(posedge bus.clk) bus.valid <= 1'b1;
endmodule

module top;
  logic clk;
  bus_if  b (clk);                   // instantiate the bundle
  master  m (.bus(b));
  slave   s (.bus(b));
endmodule

Modports: directions for each side

Inside an interface every signal is just a signal. A modport says which signals a particular user may drive and which it may only read. The compiler then rejects code that drives the wrong one.

interface bus_if (input logic clk);
  logic valid, ready;
  logic [7:0] addr;  logic [31:0] data;

  modport master  (input clk, ready, output valid, addr, data);
  modport slave   (input clk, valid, addr, data, output ready);
  modport monitor (input clk, valid, ready, addr, data);
endinterface

module master (bus_if.master bus);   // this module sees the master view

Clocking blocks

When the DUT and the testbench both react to the same clock edge, the order in which the simulator runs them is not defined. A testbench might read a signal before or after the DUT updates it: a race. A clocking block fixes the timing: inputs are sampled just before the edge, outputs are driven just after it.

interface bus_if (input logic clk);
  logic valid, ready;  logic [31:0] data;

  clocking cb @(posedge clk);
    default input #1step output #2;   // sample just before the edge, drive 2 time units after
    output valid, data;               // testbench drives these
    input  ready;                     // testbench samples this
  endclocking

  modport tb (clocking cb);
endinterface

// In the testbench:
@(bus.cb);                 // wait for the clocking event
bus.cb.valid <= 1'b1;      // drive through the clocking block (use <=)
if (bus.cb.ready) ...      // read the value sampled before the edge

Packages, import and `include

A package is a named container for types, parameters, functions and classes. import makes its names visible. `include is different: the preprocessor pastes a file's text in place, as if you had typed it there.

package alu_pkg;
  typedef enum logic [1:0] {ADD, SUB, AND_OP, OR_OP} op_t;
  parameter int WIDTH = 8;
  function automatic logic [WIDTH-1:0] model(op_t op, logic [WIDTH-1:0] a, b);
    case (op) ADD: return a + b; SUB: return a - b; AND_OP: return a & b; default: return a | b; endcase
  endfunction
endpackage

import alu_pkg::*;        // wildcard: every name, only where it is used
import alu_pkg::op_t;     // explicit: just this one name
alu_pkg::WIDTH            // scope resolution: no import needed

Parameters and type parameters

Value parameters make sizes configurable. Type parameters go further: the same FIFO code can store bytes, ints or whole structs.

module fifo #(
  parameter type T     = logic [7:0],   // type parameter
  parameter int  DEPTH = 16             // value parameter
) (
  input  logic clk, push, pop,
  input  T     din,
  output T     dout
);
  T mem [DEPTH];
  localparam int AW = $clog2(DEPTH);    // derived: address width
  logic [AW-1:0] wr_ptr, rd_ptr;
endmodule

fifo #(.T(packet_t), .DEPTH(8)) pkt_fifo (...);

Practice questions

Work these on paper first, then open the model answer.

1. Add a resp signal (2 bits, driven by the slave) to bus_if. Which lines change?

Only the interface: declare logic [1:0] resp;, add input resp to the master and monitor modports and output resp to the slave modport. Module port lists and instantiations do not change.

2. Why does a class need virtual bus_if instead of bus_if?

An interface is a static, elaborated structure like a module; it cannot be created inside a class at run time. A virtual interface is a handle that is set at run time to point to an interface instance that already exists in the module hierarchy.

3. What does default input #1step mean?

Inputs are sampled at the very end of the previous time step, i.e. just before the clock edge. The testbench therefore sees the same values the DUT's flip-flops see.

4. Two imported packages both define WIDTH. How do you use one of them?

Refer to it explicitly as pkg_a::WIDTH, or import that one name explicitly with import pkg_a::WIDTH;. A plain reference to WIDTH after two wildcard imports is an error.

5. Write a parameterised register of type T with default logic [7:0].
module dreg #(parameter type T = logic [7:0]) (
  input logic clk, input T d, output T q
);
  always_ff @(posedge clk) q <= d;
endmodule
