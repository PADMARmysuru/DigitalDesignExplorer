Test Pattern Generation (ATPG)

Instead of trying every input, ATPG algorithms work backwards from a fault to find the exact pattern that exposes it.

2

Why not apply every input combination?

A circuit with n inputs has 2n input combinations. Applying all of them is called exhaustive testing. It works for tiny circuits, but the number doubles with every extra input. Move the slider to see how long exhaustive testing would take on a tester applying 100 million patterns per second.

Automatic Test Pattern Generation (ATPG) takes the opposite approach: it picks one fault at a time and calculates a pattern that detects it. Most patterns detect many faults, so a few thousand patterns can cover millions of faults.

4

Boolean difference

The Boolean difference of output F with respect to a line x tells us when F depends on x:

dF/dx = F(x = 0) ⊕ F(x = 1)

When dF/dx = 1, flipping x flips the output, so an error on x reaches the output. Therefore:

Tests for x s-a-0: x · dF/dx = 1    Tests for x s-a-1: x̄ · dF/dx = 1

Choose a line and a fault. The table computes the Boolean difference for every pattern and marks the tests.

5

The five-valued D-calculus

To track a fault through a circuit, each line carries a pair of values: good circuit / faulty circuit.

  • D means 1 in the good circuit and 0 in the faulty circuit (1/0).
  • D̄ means 0 in the good circuit and 1 in the faulty circuit (0/1).
  • X means not yet decided.

Gates are evaluated separately on the good and faulty values. Try some combinations.

6

The D-algorithm, step by step

The D-algorithm (Roth, 1966) places a D at the fault site, drives it forward through the D-frontier (gates with D on an input and X on the output) to an output, and then justifies every value it needed. If a choice fails, it backtracks. Target: n1 stuck-at-0.

7

PODEM, step by step

PODEM (Goel, 1981) only ever assigns values to primary inputs. It repeats three moves: set an objective (a line and a value), backtrace the objective to one primary input, then imply (simulate) the result. Because decisions are made only at inputs, backtracking is simple and PODEM is usually faster than the D-algorithm. Target: n2 stuck-at-1.

Some faults have no test at all. If PODEM tries every input choice and still fails, the fault is redundant: the circuit contains logic that never affects the output. Redundant faults are removed from the coverage calculation, and the redundant logic can often be removed from the design.

10

What you learned

  • Exhaustive testing needs 2n patterns and quickly becomes impossible.
  • A test must activate the fault, propagate its effect to an output, and justify every required value from the inputs.
  • Side inputs on the propagation path need the non-controlling value: 1 for AND/NAND, 0 for OR/NOR.
  • The Boolean difference dF/dx = F(x=0) ⊕ F(x=1) shows when an output depends on a line.
  • The D-calculus tracks good/faulty values together with 0, 1, X, D and D̄.
  • The D-algorithm drives D through the D-frontier and justifies values, backtracking when needed.
  • PODEM assigns only primary inputs using objective, backtrace and implication.
  • A fault with no possible test is redundant.
