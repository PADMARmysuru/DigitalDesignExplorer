Level 6: SystemVerilog, Module 8

Constrained Randomization

Writing every test value by hand is slow and only finds the bugs you already imagined. Constrained random testing lets the simulator choose values for you, inside rules you define, so each run explores cases you never thought of.

Learning objectives

By the end of this module you will be able to:

  1. Declare random properties with rand and randc and call randomize().
  2. Write constraints with relational operators, inside and dist.
  3. Explain the difference between := and :/ weights.
  4. Use implication (->) and solve ... before to shape distributions.
  5. Add inline constraints with randomize() with { }.
  6. Use pre_randomize() and post_randomize(), and handle randomization failure.

Module 5: classes and objects.

rand, randc and randomize()

Random variables live in a class. randomize() picks new values for every rand and randc property so that all constraints are satisfied, and returns 1 on success or 0 if no solution exists.

class Txn;
  rand  bit [7:0] addr;       // rand: any legal value, repeats allowed
  rand  bit [7:0] data;
  randc bit [1:0] id;         // randc: cycles through all 4 values before repeating
  bit        [7:0] tag;       // not random: randomize() leaves it alone

  constraint c_addr { addr inside {[8'h10:8'h1F]}; }
endclass

Txn t = new();
if (!t.randomize()) $fatal(1, "randomization failed");   // ALWAYS check the result

Constraint playground

Type constraints for rand bit [W-1:0] data; and generate values. Supported here: comparisons (< <= > >= == !=), inside {...}, !(data inside {...}), data % N == M, and one dist. Each line is a separate constraint; all must hold.

Weighted distributions: := vs :/

dist makes some values more likely than others. := gives the weight to each value in a range; :/ divides the weight across the range.

Implication and solve ... before

a -> b means "if a then b". The solver picks uniformly among all legal combinations, which can make one value of a very rare. solve a before b picks a first, uniformly, then b.

class Pkt;
  rand bit       is_short;
  rand bit [2:0] len;
  constraint c_len { is_short -> len == 0; }   // short packets have length 0
  // constraint c_order { solve is_short before len; }
endclass

Inline constraints, callbacks and failure

randomize() with { ... } adds constraints for one call only. pre_randomize() runs before solving and post_randomize() after a successful solve, typically to compute derived fields such as a checksum.

class Frame;
  rand bit [7:0] len;
  rand bit [7:0] payload[];
  bit      [7:0] crc;
  constraint c_len  { len inside {[1:8]}; payload.size() == len; }

  function void pre_randomize();  $display("about to randomize"); endfunction
  function void post_randomize(); crc = payload.xor();            endfunction
endclass

Frame f = new();
ok = f.randomize() with { len == 4; };      // inline constraint

Practice questions

Work these on paper first, then open the model answer.

1. Write a constraint so that addr is word-aligned (a multiple of 4) and below 256.
constraint c_align { addr % 4 == 0; addr < 256; }

Or addr[1:0] == 2'b00;, which solvers handle more efficiently.

2. Make kind (an enum READ/WRITE/IDLE) 45% READ, 45% WRITE, 10% IDLE.
constraint c_kind { kind dist { READ := 45, WRITE := 45, IDLE := 10 }; }
3. Why check the return value of randomize()?

If constraints conflict, randomize() returns 0 and leaves the variables unchanged. The test then silently reuses old values, and you may believe you tested cases you never did.

4. How do you turn off one constraint for a single test?
t.c_addr.constraint_mode(0);   // disable
void'(t.randomize());
t.c_addr.constraint_mode(1);   // re-enable
5. What is randc useful for?

Covering every value of a small field quickly with no repeats, for example visiting all 16 register addresses or all opcodes before starting again.
