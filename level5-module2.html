Fault Models

Real defects are messy. Fault models turn them into simple, logical faults that we can simulate, count and generate tests for.

1

  • Describe wired-AND and wired-OR bridging faults
  • Explain why a CMOS stuck-open fault needs two patterns
  • Test slow-to-rise and slow-to-fall transition faults
  • Explain path delay faults and at-speed testing
  • Choose a suitable fault model for a given defect
2

Why do we need fault models?

A chip can suffer from millions of possible physical defects: particles of any size, cracks, shorts, thin oxide, weak transistors. We cannot simulate each one with transistor physics.

A fault model describes how a defect changes the logic behaviour of the circuit, using only 0s, 1s and timing. Once defects are expressed as faults, a computer can list them, simulate them and generate tests for them automatically.

Stuck-at faults

In the single stuck-at fault model we assume exactly one line in the circuit is permanently 0 (s-a-0) or 1 (s-a-1), and the gates themselves work normally. Each line has two possible faults, so a circuit with k lines has 2k single stuck-at faults.

The circuit below has 5 lines (A, B, C, n1, Y), so it has 10 single stuck-at faults. Choose any fault, then find an input combination that detects it.

If a line fans out to several gates, each branch is a separate fault site, because a defect can break one branch and not the others. Also, multiple stuck-at faults (several lines faulty at once) give 3k − 1 combinations. That is far too many to target, so tests are generated for single faults, which in practice also catch most multiple faults.
4

Bridging faults

A bridging fault is an unwanted short between two wires, for example when a metal particle joins two neighbouring lines. When both lines carry the same value nothing changes. When they carry different values, the stronger driver wins:

  • Wired-AND: the 0 wins, so both lines become 0 (common when nMOS pull-downs are stronger).
  • Wired-OR: the 1 wins, so both lines become 1.

Open faults

An open fault is a broken connection. A broken wire feeding a gate input usually acts like a stuck-at fault. A broken transistor connection inside a CMOS gate is more surprising: the stuck-open transistor can never conduct.

In this CMOS NAND gate, the pMOS transistor driven by A is stuck-open. When the input needs that transistor to pull the output high, nothing drives the output. The output node floats and keeps its previous value on its capacitance. The combinational gate suddenly behaves like a memory.

This is why a stuck-open fault needs a two-pattern test: the first pattern sets the output to the opposite value (initialisation), the second pattern tries to switch it through the broken transistor.
6

Transition faults

Some defects do not stop a signal; they only make it slow. A transition fault assumes one node is too slow to change:

  • Slow-to-rise (STR): the 0 → 1 change arrives too late.
  • Slow-to-fall (STF): the 1 → 0 change arrives too late.

The test uses two patterns. V1 sets the node to the starting value, V2 launches the transition, and the output is captured one clock period later. Here the faulty node is the output Y of an AND gate. Pick V1 and V2 and watch the waveforms.

7

Path delay faults

A path delay fault looks at a whole path from a flip-flop, through several gates, to the next flip-flop. Each gate may be only a little slow, but if the total delay along the path exceeds the clock period (minus setup time), the wrong value is captured.

Use the sliders. Notice that a small extra delay is invisible at a slow test clock and appears only when you test at the real operating speed. That is why modern chips use at-speed testing.

What you learned

  • Fault models turn countless physical defects into a small set of logical faults that tools can handle.
  • The single stuck-at model gives 2 faults per line and is the industry's basic test target.
  • Multiple stuck-at faults are too many to target, but single stuck-at tests catch most of them.
  • Bridging faults short two lines; the result is wired-AND or wired-OR depending on which driver is stronger.
  • A CMOS stuck-open fault makes the output float and remember its old value, so it needs a two-pattern test.
  • Transition faults (slow-to-rise, slow-to-fall) need an initialising pattern, a launch pattern and an at-speed capture.
  • Path delay faults model the total delay along a path and are only visible when testing at the real clock speed.
