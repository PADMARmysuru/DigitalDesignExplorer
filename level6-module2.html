Level 6: SystemVerilog, Module 2

Procedural SystemVerilog

Procedural code describes what happens on each clock edge or whenever an input changes. SystemVerilog adds blocks that state your intent, and loops and case forms that make intent checkable.

Learning objectives

By the end of this module you will be able to:

  1. Choose between always_comb, always_ff and always_latch, and explain what each checks.
  2. Predict the result of blocking (=) and non-blocking (<=) assignments step by step.
  3. Explain how case, casez and casex treat X and Z, and what unique and priority add.
  4. Trace for, while, do-while, repeat and foreach loops, including break and continue.
  5. Spot code that accidentally creates a latch.

Module 1: logic, nets vs variables, and literals such as '0.

Three blocks that state your intent

Verilog's plain always can describe any logic, so the tool must guess what you meant. SystemVerilog's specialised blocks tell the tool, and it warns you when the code doesn't match.

BlockDescribesSensitivityTool checks
always_combCombinational logicAutomatic (every signal read)No latches inferred; one block drives each variable
always_ffFlip-flopsYou write @(posedge clk ...)Exactly one event control; code should infer flops
always_latchLevel-sensitive latchesAutomaticCode should infer a latch
always_comb begin            // combinational: y updates whenever a, b or sel change
  if (sel) y = a;
  else     y = b;
end

always_ff @(posedge clk or negedge rst_n)   // flip-flop with async active-low reset
  if (!rst_n) q <= '0;
  else        q <= d;

always_latch                 // transparent latch
  if (en) l <= d;

always_comb also runs once at time 0, so outputs are correct from the start. A Verilog always @(*) waits for the first input change.

Blocking vs non-blocking assignment

= (blocking) updates the variable immediately, before the next statement runs. <= (non-blocking) reads the right-hand side now but updates the variable only after every block triggered by this clock edge has finished.

The rule every RTL designer follows: use <= in always_ff and = in always_comb. Never mix both styles on one variable.

Decisions: if, case, casez, casex

A case compares the selector with each item from top to bottom and takes the first match. The three forms differ only in how they treat X, Z and ? bits.

FormDon't-care bitsTypical use
caseNone. X matches only X, Z only ZNormal decoding
casezZ or ? in selector or itemPriority encoders, instruction decoding with ?
casexX, Z or ? in selector or itemAvoid in RTL: an X on the selector can silently match an item

unique case: the items never overlap and one always matches, so synthesis may build parallel logic. priority case: take the first match, and at least one must match. Both produce simulation warnings when the promise is broken, which catches bugs early.

Loops

Loops run in zero simulation time unless they contain a delay or event control. In RTL, a loop is unrolled into copies of hardware, so its bounds must be fixed at compile time.

Accidental latches

If a combinational block does not assign a variable on every path, the variable must remember its old value, and remembering means a latch. always_comb turns this mistake into a warning or error.

always_comb
  if (en) y = d;      // what is y when en == 0?  -> latch!

always_comb begin
  y = '0;             // default assignment first: every path now assigns y
  if (en) y = d;
end

Practice questions

Work these on paper first, then open the model answer.

1. Why does always_ff use <=?

All flip-flops in real hardware sample their inputs at the same clock edge. <= models this: every right-hand side is read before any register updates, so the order of statements and blocks does not change the result.

2. Rewrite this so it has no latch: always_comb case (s) 2'd0: y = a; 2'd1: y = b; endcase
always_comb
  case (s)
    2'd0:    y = a;
    2'd1:    y = b;
    default: y = '0;
  endcase

A default assignment before the case works too.

3. What is printed? for (int i = 0; i < 6; i++) begin if (i == 1) continue; if (i == 4) break; $display(i); end

0, 2, 3. continue skips the rest of the body for i = 1; break leaves the loop at i = 4.

4. Why is casex dangerous in RTL?

If the selector becomes X in simulation (for example, it was never reset), casex treats those X bits as don't-care and matches an item anyway. The simulation looks fine while real hardware would do something unpredictable. casez or case ... inside avoids this.

5. When does a do-while behave differently from a while?

When the condition is false at the start. while checks first and runs the body zero times; do-while runs the body once, then checks.
